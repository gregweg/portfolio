Orchestration and Eval Learnings: Security, GPU Management, and Observability

Today's notes delve into the intricate world of orchestrating machine learning (ML) workloads securely and efficiently. The final section focuses on modern observability tools that help in tracking user behavior and AI model performance.

Orchestration and Eval Learnings

Security in ML Infrastructure

Runtime & Tenante Isolation

- Multi-Tenant Clusters: Isolate namespaces in Kubernetes to keep team workloads separated.
    - mTLS (Mutual Transport Layer Security): A process where both client and server verify each other's cryptographic keys before establishing a connection. Used for securing inter-node worker communication (Ray nodes) against eavesdropping or unauthorized traffic.
- Code Sandboxing: Isolate execution environments when running unverified or user-submitted code.
    - eBPF (Extended Berkeley Packer Filter): A kernel-level technology that allows programs to run directly inside the Linux kernel without modifying source code. Used for deep, low-overhead security monitoring and tracing at the system level.
    - gVisor: An open-source, user-space kernel that acts as a secure sandbox layer between an application and the host OS kernel, preventing malicious code execution from compromising the host.

Data & Artifact Access Control

Identity Management: Use pod/worker-level IAM roles (AWS IRSA, GCP Workload Identity) over static credentials.

- IRSA (IAM Roles for Service Accounts): An AWS mechanism that maps IAM permissions directly to specfic Kubernetes service accounts instead of sharing broad, hardcoded node credentials.

Storage Protection: Enforce strict bucket policies (S3/GCS) and KMS encryption at rest and in transit for model weights, artifacts, and sensitive training datasets.

API & Gateway Security

  • Authentication: Implement OAuth2 / JWT (JSON Web Tokens) for external inference APIs.
  • Network Policies: Restrict outbound (egress) traffic from compute nodes to prevent data exfiltration. Guard endpoints against prompt injection and malicious payloads at the API gateway layer.

GPU Allocation & Compute Orchestration

Scheduling & Sharing Strategies

  • Spatial Sharing (Physical Splitting):
    • NVIDA MIG (Multi-Instance GPU): A technology on NVIDIA A100/H100 GPUs that physocally partitions a single GPU into up to seven fully isolated instances, each with its own dedicated high-bandwidth memory and compute cores.
  • Temporal Sharing (Time Splitting):
    • CUDE Time-Slicing: A software-based approach where multiple processes share a single GPU by taking turns using the processing cores over time, similar to CPU time-sharing.
  • Allocation Strategy: Use temporal/spatial sharing for light microservices or development environments, and switch to dedicated node affinity (100% GPU reserved) for large distributed training tasks.

Core Observability Pillars for Unique AI Interfaces

Native AI Tracing & Model Evals

Langfuse (Open-Source / Managed): Excellent for tracking complex generation chains, dynamic batching costs and model latency. Integrates easily with OpenTelemetry.

Braintrust: FOcuses heavily on automated evaluation pipelines (LLM-as-a-Judge). ALlows you to continuously score model predictions against human overrides to catch quality regreressins during rapid deploys.

Comet Opik: Open-source framework designed for evaluation and tracing across model version iterations.

AI-Aware Product Analytics & Session Replay

Since your interface introduces a new design pattern, seeing what users do when an AI forecast appears is critical.

  • PostHog: COmbines session recordings, event- based product analytics, and native LLM trace inestion via OpenLLMetry. Watching session replays when users manually override or edit an AI-generated forecast provides immediate UX feedback.

  • Mixpanel + Custom Event Metadata: Tracks aggregate cohort behavior and conversion funnels specifically to AI feature exposure.

Standard Infrastructure Telemetry

  • OpenTelelmetry(Otel): The industry standard for instrumentation. Using OTel libraries prevents vendor lock-in, allowing you to stream traces to any backend (Datadog, Grafana, PostHog, or Langufe) via standard SDK hooks.

  • Instrument with OpenTelemetry First: Avoid proprietary SDKs where possible. Standardize backend logging around OTel gen_ai.* trace conventions so you can swap or multi-home your observability backends without rewriting application logic.

  • Log User Overrides as Ground Truth: Whenever a user edits an AI forecast on your interface, capture the initial forecast vs. the user's corrected value as a telemetry event. This forms your baseline evaluation dataset for fine-tuning.
