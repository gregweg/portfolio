Cancel Needs a definted State-Transition Policy:

pending_payment → cancelled     allowed
paid            → cancelled     perhaps requires a refund
cancelled       → cancelled     replay/no-op
cancelled       → paid          forbidden

Idempotency contract

Persist something equivalent to:

IdempotencyRecords

scope string
key string
request_fingerprint string
status enum(in_progress, completed)
response_status integer nullable
response_body object nullable
created_at timestamp
expires_at timestamp
UNIQUE(scope, key)

Behavior:
- Same key and same normalized request: replay the original status and response.
- Same key with a different request: return 409 Conflict.
- Same key while the first request is running: return the eventual response, or a documented 409/425.
- No key for an endpoint requiring one: return 400 Bad Request.
- Scope keys by caller and operation, not globally.
- Create the idempotency record and business mutation atomically when they share a database.
