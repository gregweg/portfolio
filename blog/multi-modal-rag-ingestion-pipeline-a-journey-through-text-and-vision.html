Multi-Modal RAG Ingestion Pipeline: A Journey Through Text and Vision

Today, I'm diving deep into the challenges and opportunities of creating an ingestion pipeline for multimodal RAG (Retrieval-Augmented Generation) systems. The goal is to build a robust system that can handle various file types—ranging from simple text documents to complex images and PDFs—and convert them into structured data ready for machine learning models. This work is crucial as I aim to create an efficient, scalable solution that leverages both local and cloud-based AI resources.

OpenAI & Claude both support vision workflows for image understanding, OCR-like extractions, charts, diagrams, and document/image reasoning. OpenAI's vision models can analyze images and text inside images, while Claude's vision/PDF docs describe visual understanding for images and PDFs, including charts and layouts.

Ollama is useful as the local model runner for open models and fallbacks.

RAG System, ingestion in three phases.

1. Raw source
   - original PDF/image/text
   - stored unchanged

2. Extracted learning content
   - text
   - OCR
   - image descriptions
   - diagram explanations
   - table markdown
   - equations
   - page summaries

3. Retrieval chunks
   - small chunks for search
   - metadata-rich
   - connected back to page/image coordinates

Tiered Model Routing:

Tier 1: Cheap/local
  Ollama + Qwen
  - simple OCR cleanup
  - summarization
  - classification
  - concept tagging
  - duplicate detection
  - low-risk chunks

Tier 2: Cloud quality
  GPT / Claude
  - complex diagrams
  - handwritten notes
  - charts
  - math reasoning
  - ambiguous pages
  - final validation

Tier 3: Human review / async retry
  - failed extraction
  - low confidence
  - important curriculum material

Multi-Tenant Row Level Isolation in Postgres

Add tenant_id to every tenant-owned table

Enable Row Level Security

Set the current tenant in the DB session/transaction

Write policies that only allow rows where tenant_id = current_setting(...)

Make Sure app roles cannot bypass RLS

CREATE TABLE orders (
  id uuid PRIMARY KEY,
  tenant_id uuid NOT NULL,
  customer_name text NOT NULL,
  total_cents integer NOT NULL
);

ALTER TABLE orders ENABLE ROW LEVEL SECURITY;
ALTER TABLE orders FORCE ROW LEVEL SECURITY;

Create a policy:

CREATE POLICY tenant_isolation_orders
ON orders
USING (
  tenant_id = current_setting('app.current_tenant_id')::uuid
)
WITH CHECK (
  tenant_id = current_setting('app.current_tenant_id')::uuid
);

In the application, set the tenant per transaction.

BEGIN;

SET LOCAL app.current_tenant_id = '6b3f7b7e-4c1a-4db2-9349-6e8b3df2c001';

SELECT * FROM orders;

COMMIT;
