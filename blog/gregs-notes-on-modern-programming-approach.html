Greg's Notes on Modern Programming Approach

Today's jottings revolve around refining my approach to software development. As a systems and AI engineer, I’m increasingly reliant on clear specifications and iterative refinement to tackle complex tasks efficiently. By integrating large language models into my workflow, I aim to streamline the process of clarifying goals and managing ambiguities.

My Modern Programming Approach

Goal Task Deconstruction

Plan-Then-Execute

Approach

  • Internalize Domain and Utilities

  • Spec Driven Design

  • Ideate with LLM to craft spec

  • Clarify and Identify ambiguities

  • Finalize Spec & Evaluation / Success Criteria

  • Covering for Edge Cases

Spec-Driven Agentic Development Workflow

1. Intent Capture

Input:
- Human request
- Business goal
- User problem
- Existing repo/context

Output:
- Problem statement
- Success criteria
- Non-goals
- Open questions

2. Spec Generation

Agent creates:
- Functional requirements
- Non-functional requirements
- Data model changes
- API/interface changes
- UX/admin behavior
- Security/permissions
- Observability needs
- Acceptance criteria

3. Spec Refinement

Loop until stable:
- Identify ambiguity
- Ask targeted questions
- Split large scope into phases
- Define edge cases
- Mark assumptions explicitly

4. Design / Architecture Plan

Create:
- Components touched
- Ownership boundaries
- Data flow
- Failure modes
- Rollback plan
- Migration strategy
- Dependency risks

5. Implementation Plan

Create small executable tasks:
- Task ID
- Files likely touched
- Expected behavior
- Test expectations
- Definition of done

6. Build Execution

Coding agent works task-by-task:
- Reads spec
- Implements smallest safe change
- Updates docs/tests
- Produces PR summary

7. Testing

Run:
- Unit tests
- Integration tests
- Contract/API tests
- Migration tests
- Permission tests
- Regression tests

8. Evaluation

Evaluate against:
- Golden scenarios
- Acceptance criteria
- Edge cases
- Security constraints
- Performance budget
- Hallucination/spec-drift checks

9. Review

Reviewer checks:
- Does code match spec?
- Did agent overbuild?
- Were assumptions introduced?
- Are tests meaningful?
- Are eval failures explained?

10. Feedback Loop

Failures update:
- Spec
- Test cases
- Eval dataset
- Agent instructions
- Implementation plan

Still chewing on: Reflecting on today's exploration, it strikes me how crucial it is to maintain a balance between the precision needed for spec-driven development and the adaptability required in agile environments. How do we ensure our specifications remain flexible enough while avoiding drift that could derail projects?
